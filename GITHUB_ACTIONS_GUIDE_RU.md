# Загрузка MRTT через GitHub Desktop и сборка APK в отдельной ветке

Инструкция для Windows 10/11, **существующего приватного репозитория**
https://github.com/ttrroyy/mrtt-test, GitHub Desktop и Проводника Windows.
Редактор VS Code можно использовать для просмотра изменений, но для загрузки он не требуется.
**Git Bash / терминал / Git для Windows устанавливать отдельно не нужно.**

Цель: сохранить `main` неизменной, создать `max-test`, загрузить весь исходный код и
автоматически собрать APK с именем приложения **MRTT**.

## Шаг 1. Распаковать новый ZIP

1. Скачайте `mrtt-max-branch-apk-2026-10-22.zip` на ПК.
2. Правой кнопкой по ZIP → **Извлечь всё** (или используйте архиватор).
3. Откройте папку `mrtt-test-main` **внутри** распакованного архива.
   В ней должны находиться `app`, `rust-client`, `rust-server`, `scripts`, `.github`, `gradlew`.
   **Копировать нужно содержимое этой папки, а не ZIP и не папку целиком.**

## Шаг 2. Клонировать существующий приватный репозиторий

1. Запустите **GitHub Desktop** и войдите в нужный GitHub-аккаунт.
2. Меню **File → Clone repository… → URL**.
3. В поле URL вставьте `https://github.com/ttrroyy/mrtt-test`.
4. В **Local path** выберите удобное место, например `Документы/GitHub/mrtt-test`.
5. Нажмите **Clone**.

Не выбирайте **Create a New Repository**: репозиторий уже существует.
Если репозиторий не открывается, проверьте, что вы вошли в аккаунт с доступом к приватному репо.

## Шаг 3. Создать отдельную ветку ДО копирования

1. В GitHub Desktop выберите **Current Branch** (вверху).
2. Нажмите **New Branch**.
3. Введите **`max-test`**.
4. В качестве основы выберите **`main`** (если предложат выбрать).
5. Нажмите **Create Branch**.
6. Проверьте, что вверху написано **Current Branch: max-test**.

⚠️ Дальше работайте **только с `max-test`**. Не переключайтесь на `main` до публикации коммита.

## Шаг 4. Поместить исходники в клонированный репозиторий

1. В GitHub Desktop: **Repository → Show in Explorer**. Откроется локальная папка репозитория.
2. В другом окне Проводника откройте распакованную папку `mrtt-test-main` из шага 1.
3. Внутри неё нажмите **Ctrl+A → Ctrl+C**.
4. Перейдите в открытую GitHub Desktop папку репозитория → **Ctrl+V**.
5. На вопрос о замене файлов выберите **Replace the files in the destination / Заменить файлы**.

**Проверьте структуру:** непосредственно в корне клонированного репозитория
должны быть `app/`, `rust-client/`, `rust-server/`, `.github/workflows/build-test-apk.yml`, `gradlew`.
Не должно быть лишнего вложенного `mrtt-test-main/mrtt-test-main/`.
**Никогда не удаляйте `.git`** внутри клонированного репозитория.

В GitHub Desktop откройте вкладку **Changes**. Должны появиться изменённые/новые файлы.
Если изменения отсутствуют, скорее всего, файлы скопированы не в ту папку.

## Шаг 5. Коммит и отправка ветки на GitHub

1. В GitHub Desktop внизу слева, в поле **Summary**, введите:
   `Add MAX transport and MRTT Android CI`
2. Убедитесь, что кнопка называется **Commit to max-test**, и нажмите её.
3. Нажмите **Publish branch** (или **Push origin**, если ветка уже существует удалённо).
4. Дождитесь окончания загрузки файлов. GitHub Desktop передаст их в приватный репозиторий.

Зайдите на https://github.com/ttrroyy/mrtt-test и выберите ветку **max-test**
в списке веток: там должны быть исходники и `.github/workflows/build-test-apk.yml`.
**Не нажимайте Merge pull request** и не вносите файлы в `main`.

## Шаг 6. GitHub Actions запускается автоматически

В новом архиве workflow находится в `.github/workflows/build-test-apk.yml` и имеет триггер:

```yaml
on:
  push:
    branches:
      - max-test
  workflow_dispatch:
```

Как только GitHub Desktop выполнит **Publish branch / Push origin** с новым коммитом,
GitHub Actions автоматически запустит сборку. Перейдите на
https://github.com/ttrroyy/mrtt-test/actions
и найдите запуск с именем **Build MRTT APK (max-test)**, ветка `max-test`.

Если он не появился: проверьте **Settings → Actions → General** и права на Actions
(для приватных репозиториев Actions могут быть отключены). Убедитесь, что в
`max-test` загружен настоящий YAML-файл, а не сам ZIP.

**Не ищите кнопку `Run workflow` в качестве обязательного шага:** ручной запуск
`workflow_dispatch` может быть недоступен, пока workflow не существует в default branch
(`main`). Автоматический `push` в `max-test` работает без переноса workflow в `main`.
Для повторной сборки внесите небольшой коммит в `max-test` и нажмите **Push origin**.

## Шаг 7. Скачать готовый APK

1. На странице Actions откройте **Build MRTT APK (max-test)** → последний запуск
   ветки `max-test`.
2. Откройте задачу **Build Android APK (VK + MAX)** и проверьте зелёную галочку.
3. Вернитесь на страницу запуска. Внизу найдите **Artifacts** → **MRTT-max-test-APKs**.
4. Скачайте ZIP-артефакт и распакуйте его.
5. Установите `app-arm64-v8a-maxTest.apk` для большинства современных Android либо
   `app-universal-maxTest.apk`, если архитектура неизвестна.

**Имя приложения на телефоне: MRTT.**
Debug APK имеет отдельный идентификатор пакета `app.mrtt.debug`,
поэтому устанавливается рядом с исходным MRTT. Однако Android может потребовать
удалить более старый debug APK при смене подписи между сборками GitHub Actions.

## Что именно собирает и чего не делает workflow

- Сборка Linux-сервера для упаковки в приложение, Rust-клиента для Android,
  unit-тесты и оптимизированный APK maxTest с нативным транспортом VK/MAX.
- **Не деплоит VPS самостоятельно** и не меняет уже работающий сервер.
- Генерация ссылок обновлённой серверной панелью — только `mrtt://`.
  Старые `mrtt://` новая версия приложения отклоняет.
- Для проверки MAX нажмите «Привязать MAX», войдите в аккаунт и откройте
  группу. Токен и группа сохранятся автоматически. Нужен реальный тест соединения. Успешный APK не доказывает доступность MAX TURN.

Если сборка покраснела: откройте первый упавший шаг в Actions, отправьте его название
и последние 60–100 строк (но не ключи/токены).

## Возможные ошибки загрузки

- **Не вижу `max-test` на GitHub:** нажмите **Publish branch** в GitHub Desktop.
- **Изменения оказались в `main`:** остановитесь до Push, переключитесь в `max-test`
  и перенесите ещё не закоммиченные изменения через диалог GitHub Desktop.
- **Нет `.github/workflows/build-test-apk.yml`:** скопировали не всё содержимое ZIP.
- **Двойная папка:** `mrtt-test-main` должна распаковываться отдельно, но её
  содержимое копируется в *корень* клонированного репозитория.
- **Не устанавливается очередной debug APK:** удалите предыдущую тестовую версию
  MRTT, после чего установите новую (локальные настройки тестовой версии исчезнут).
