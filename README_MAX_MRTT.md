# MRTT / MAX (экспериментальная интеграция)

**Статус:** исходный код для опытной сборки; реальные MAX API / TURN / Android APK **не были проверены на живом аккаунте**. Автономная поддержка MAX может потребовать адаптации при изменении API MAX. Код не содержит учётных данных.

## Что именно реализовано

- Старый VK-режим не удалён; в рамках одного запущенного клиента выбирается **либо VK, либо MAX**, но разные клиенты могут использовать разные транспорты к одному и тому же MRTT-серверу.
- `rust-client/max_calls.rs`: WS `wss://ws-api.oneme.ru/websocket` (opcode 6 → 19 → 158), `auth.anonymLogin`, `system.getInfo`, `vchat.startConversation` в указанной MAX-группе, `vchat.getConversationParams` для получения TURN-параметров и обновления учётных данных воркеров. Вызовы и параметры адаптированы из `tools/MrttMaxToken`.
- Android: настройки MAX (ID группы и зашифрованный локально токен), запуск `--max GROUP_ID`, передача токена через stdin `MAX_BOOTSTRAP:<base64(JSON)>`, без записи токена в аргументы процесса/ссылку.
- Схема ссылок при генерации и импорте — **только** `mrtt://`; старые `mrtt://`-ссылки отклоняются.
- `scripts/make_mrtt_link.py`: шифрованные ссылки с параметром `max=<group_id>` для MAX либо `hashes=<VK_hashes>` для VK. Существующая серверная панель по умолчанию продолжает формировать ссылки для VK, но уже с префиксом `mrtt://`. Для MAX сгенерируйте ссылку отдельно этим скриптом.

## Настройка MAX и проверка

1. Нажмите **Туннель → MAX → «Привязать MAX»**, войдите в аккаунт и откройте нужную группу. Если группа задана в ссылке подключения, приложение откроет её после входа. Токен и ID группы сохраняются автоматически, без ручных полей или импорта файлов.
2. Дождитесь статуса **«Токен и группа привязаны»** и нажмите **«Готово»**, затем выберите транспорт **MAX**. До обнаружения группы получение токена не считается завершённой привязкой. Сессия MAX сохраняется при закрытии окна и перезапуске приложения; обычное подключение не открывает окно входа. Токен хранится в зашифрованных настройках профиля. При отзыве сессии в MAX потребуется повторная привязка.
3. Сформируйте ссылку для MAX на своей машине (один раз требуется `python -m pip install cryptography`):

   ```powershell
   python scripts/make_mrtt_link.py --host vpn.example.com --peer 46000 --password 'YOUR_MRTT_PASSWORD' --max=-12345678
   ```

   Полученную **шифрованную** ссылку `mrtt://...` используйте в режиме подключения по ссылке. Она содержит параметры MRTT и ID группы, но не MAX-токен. Для VK ссылка генерируется серверной панелью либо скриптом с `--hashes 'VK_HASH'` вместо `--max`.
4. Разверните **обычный сервер MRTT**. Серверу не нужен токен MAX, ID группы или второй «MAX сервер»: он слушает UDP-порт peer и обрабатывает уже прибывшие из TURN пакеты. Пользовательский клиент отправляет трафик через TURN MAX. Порт сервера и пароль в ссылке должны совпадать с сервером.
5. Проверяйте логи клиента с префиксом `[MAX]`, получение TURN-параметров, успешный ICE/TURN allocate, появление туннельного IP, передачу пакетов и скорость. Переключитесь на VK, чтобы проверить отсутствие регрессий.

## Сборка исходного кода (Windows)

Используйте **весь архив**, распаковывая в корень репозитория. Последовательность важна:

1. `rust-server\build_linux.bat` — собирает серверные Linux-бинарники, нужные `deploy.sh`, и пишет provenance.
2. `rust-client\build_so.bat` — собирает Android Rust клиент для поддерживаемых ABI и обновляет их provenance. Требуются Rust toolchain, `cargo-ndk`, NDK и зависимости проекта; новый клиент дополнительно требует `futures` и `tokio-tungstenite`, указанные в `Cargo.toml`. Для тестирования на GitHub также добавлена ручная сборка debug APK (см. ниже).
3. `scripts\build_apk.bat` — проверяет provenance и создаёт APK в `app\release`.
4. В установленном приложении запустите штатную установку/обновление сервера. Если вы сменили адрес/домен доставки серверных артефактов, проверьте конфигурацию раздачи бинарников и существующую процедуру `deploy.sh`: правки MAX не подменяют её.

**Предостережение:** ранее собранные `libclient.so` и APK из другой версии не содержат MAX. Изменение исходников **не равно** успешной сборке APK или обновлению сервера. В исходном архиве нет готовых ABI `.so`.

## Протокольные ограничения и диагностика

- Авторизация MAX рассчитана на токен `__oneme_auth` (получается через `tools/MrttMaxToken` или окно входа в приложении), не на токен VK. Токен может истечь или быть отозван, потребуется повторно получить и сохранить.
- MAX «создатель» остаётся в звонке до остановки клиента. Отдельные TURN-сессии воркеров получают параметры по общему `conversationId`. Допустимость такого многократного обращения, лимиты и жизненный цикл группового звонка нужно подтвердить в настоящем MAX; это наиболее рискованная часть предлагаемой схемы.
- MAX WebSocket может требовать браузерные cookies/специфические заголовки или менять формат ответа. При 401/403 сначала проверьте свежесть токена и WebSocket/HTTP ответы относительно экстрактора. Не храните реальные ответы с токенами в публичных логах.
- В MAX-режиме **одна группа** в одном процессе. Строки из нескольких ID через запятую не поддерживаются. Режим VK одновременно с MAX в одном процессе не запускается.
- Если получен ошибочный `conversationId` или сервер ограничивает `getConversationParams` для других `session_key`, приложение покажет ошибку. Это не исправляется заменой ссылки или изменением настроек `rust-server`.

## Проверки и прозрачность

В среде подготовки архива **не установлены** Rust/Cargo, Android SDK/NDK, Gradle-cache и .NET SDK, поэтому `cargo check`, `cargo test` и сборка APK здесь **не выполнены**. Проверены упаковка файлов, синтаксис Bash и round-trip шифрования/дешифрования ссылок Python. Тесты MAX на живом сервисе остаются за пользователем после сборки.

## GitHub Actions: тестовое APK для приватного репозитория

Подробная пошаговая инструкция по загрузке ZIP в существующий приватный репозиторий и скачиванию APK: **`GITHUB_ACTIONS_GUIDE_RU.md`**.

Workflow `.github/workflows/build-test-apk.yml` **автоматически запускается после отправки коммита в `max-test`**. Сначала выполняются Android unit-тесты, затем собираются Linux-сервер, Rust-клиент для всех Android ABI и оптимизированный APK `maxTest` (R8, без отладочного режима). Артефакт: **`MRTT-max-test-APKs`**.

- Название приложения на телефоне **MRTT**, Android package ID тестовой сборки заканчивается на `.maxdebug`. Она устанавливается рядом с обычным MRTT и подписывается отладочным ключом GitHub-runner без release keystore. При смене ключа между запусками Android может потребовать переустановку, удаляющую локальные настройки и сессию.
- Репозиторий остаётся приватным, артефакты доступны авторизованным участникам с доступом к Actions. Не публикуйте access token MAX или secrets.
- Работоспособность этого workflow нельзя подтвердить до запуска в GitHub Actions с загрузкой SDK/NDK/Cargo/Gradle. Если job падает, сначала смотрите **первый** упавший шаг, а не пытайтесь установить старый APK.
- APK появляется **после зелёной сборки** в Actions → конкретный запуск → Artifacts. Для большинства телефонов нужен `app-arm64-v8a-maxTest.apk`, для остальных — `app-universal-maxTest.apk`.
- Обычный deployment/веб-панель сервера НЕ обновляются запуском workflow: для получения `mrtt://` с панели нужен **обновлённый сервер** (см. выше). Для первой проверки MAX можно вручную сделать зашифрованную ссылку через `scripts/make_mrtt_link.py`.
- Для загрузки без командной строки используйте GitHub Desktop: **Clone repository → Current Branch → New Branch (`max-test`) → скопировать содержимое ZIP → Commit to max-test → Publish branch**. Не публикуйте `local.properties` и `call.json` с приватными данными.

### Только новая схема ссылок

- `rust-server/web_panel.rs` выдаёт `mrtt://`.
- AndroidManifest и парсер принимают только `mrtt://` с зашифрованным payload. Старый `mrtt://` отклоняется, в том числе если его содержимое зашифровано корректно.
- Это **не** означает удаления транспорта VK: VK и MAX остаются доступными при создании/использовании новых `mrtt://` ссылок.
- Старые `mrtt://` ссылки придётся пересоздать в панели обновлённого сервера либо вручную в формате `mrtt://`.
